## Why Some Tasks Stay "Just Me"

Two important tasks are intentionally kept as **Just Me**:

### 1. Attending Lectures

AI cannot replace active participation in lectures. Understanding explanations directly from instructors, asking questions, and participating in class are important parts of learning.

### 2. DSA Practice

I need to develop my own problem-solving ability. If AI solves every DSA problem for me, I may produce correct answers without developing the underlying reasoning skills.

AI can therefore be used as a tutor or hint provider, but the actual problem-solving process should remain primarily mine.

## Three Target Tasks

I selected three workflows that I will continue using in **FL-02 through FL-04**.

### 1. DSA Practice

**Workflow:**

1. Read and understand the problem.
2. Attempt the problem independently.
3. If stuck, use AI for hints rather than immediately requesting the full solution.
4. Implement the solution myself.
5. Test the solution.
6. Explain the approach and complexity independently.

**Done well means:**

- I make an independent attempt before using AI.
- I understand the final algorithm.
- I can explain the solution without copying AI's explanation.
- I can state the time and space complexity.
- My implementation passes the relevant test cases.

---

### 2. Debugging

**Workflow:**

1. Reproduce the bug.
2. Inspect the error message and relevant code.
3. Ask AI to suggest possible causes.
4. Evaluate the suggestions.
5. Apply the appropriate fix myself.
6. Run tests and verify the behavior.

**Done well means:**

- The original bug can be reproduced.
- AI suggestions are treated as hypotheses rather than facts.
- The fix is tested locally.
- Existing functionality is not unintentionally broken.
- Relevant tests pass after the fix.

---

### 3. Project Documentation

**Workflow:**

1. Collect the actual project information.
2. Use AI to create an initial documentation draft.
3. Compare the draft against the source code.
4. Correct inaccurate or missing information.
5. Add setup, usage, and technical details.
6. Perform a final review.

**Done well means:**

- Every technical claim matches the actual project.
- Installation and setup instructions work.
- Usage examples are accurate.
- Important dependencies and environment variables are documented.
- The documentation is understandable to a new contributor.

## Responsible AI Principles

My approach to AI is based on **collaboration rather than replacement**.

I will:

- Verify important AI-generated information.
- Avoid blindly copying AI-generated code.
- Maintain ownership of my assignments and projects.
